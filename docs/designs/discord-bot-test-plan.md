# GearFlow Discord Bot — Test Plan
Generated by /autoplan (Phase 3 Eng) 2026-06-04. Both eng voices agree.

**Coverage rule (echoes CLAUDE.md PDF lesson):** bot-layer unit tests alone are insufficient. Every data-shape path (outbox payload, fault mapping, link binding) needs ≥1 full-pipeline integration test (service → DB → route → bot consume). The dangerous bugs live at the seams.

## Highest-risk untested path (both voices)
**Project create / crew assignment commits while Discord is down, then the bot recovers — without duplicate channels or missed permissions.** This is the single most important integration test.

| # | New codepath | Test type | Must assert |
|---|---|---|---|
| 1 | Outbox emission | Integration (Prisma txn) | Forced parent-txn rollback ⇒ **NO** outbox row exists. (The whole point of the design.) |
| 2 | Outbox consume/cursor | Integration | Bot crash mid-batch resumes from cursor: no gaps, no double-apply (at-least-once + dedupe). Lost cursor does NOT replay from 0. Duplicate poll workers don't double-process (row claim/lock). |
| 3 | Trust boundary auth | Unit + integration | Request signed with org A secret targeting org B ⇒ 401/403. Missing/invalid HMAC, stale timestamp, replayed nonce, disabled integration, tampered body all fail. Timing-safe compare (existing `verifyWebhookSignature` throws on length mismatch — discord route must try/catch like woo route). |
| 4 | `requirePermission` reuse outside session | Integration | Bot route → shared service with synthetic actor ⇒ permission ACTUALLY enforced (not bypassed for lack of session). Low-privilege linked crew DENIED `/asset fault` status flip. |
| 5 | `/link` enrollment (security) | Integration + security | (a) **Wrong-identity binding:** attacker triggers link for victim email, clicks with own Discord acct ⇒ MUST NOT attach attacker's Discord ID. (b) Enumeration response byte-identical for found/not-found. (c) Token single-use (2nd hit fails). (d) Rate-limit enforced (per Discord user + per email). (e) Null email + cross-org email cannot link. |
| 6 | Channel sync idempotency | Integration (mock discord.js) | Two `project.created` for same project ⇒ exactly ONE channel (`discordChannelId` guard). Link-after-assignment retroactively grants access. Unlinked crew ⇒ no-op + sync warning, doesn't fail whole sync. `isTemplate:true` ⇒ no channel. |
| 7 | `/asset fault` | Integration | `createdById` FK with a non-User CrewMember ⇒ no 500, correct fallback. Severity mapping rejects `out_of_service`/no `TOTAL` leak. `holdForRepair` ⇒ status→IN_MAINTENANCE in same txn. Concurrent warehouse write loses cleanly (conditional update guarded on current status). |
| 8 | Command auth gating | Unit | Role checked LIVE per interaction (no caching). Demoted user gated correctly on next command. |
| 9 | PDF delivery | Integration | `generatePdf` called outside request with correct `(projectId, orgId, docType)`; org-scoping denies cross-org. PDF > Discord attach cap (8/25MB) ⇒ graceful fallback to link. |

## Build sequence (both voices)
1. Outbox + trust boundary + shared-service refactor (nothing reliable/secure without these)
2. `/link` hardening (security-mandatory; identity-binding + org-scoped email are non-negotiable)
3. Channel sync (`discordChannelId` guard + link-time retroactive grant = the easy-to-miss items)
4. `/asset fault` (resolve `createdById` FK decision before coding)
