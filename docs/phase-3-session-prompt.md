## Phase 3 scope (WS2 — the exact deliverables)

1. **Security baseline — MANDATORY, build FIRST as shared infra** (the mutation is the boundary now, no server action in front):
   - **`resolveActor(ctx, supplied)`** — identity from `ctx.auth.getUserIdentity()`, NEVER a client arg. User tokens get the verified identity; the currently-spoofable `actor` arg is overwritten. (This closes a real actor-spoofing hole that is now load-bearing.) Audit every mutation that takes an `actor`/`actingUser` arg.
   - **Strict `v.*` arg validators + `returns` validators on every PUBLIC function** (Convex rejects undeclared fields → clients can't smuggle data).
   - **Per-doc / per-item `organizationId` re-check on every row touched** — `by_cuid`/`by_modelId` are GLOBAL indexes; one missed org check = cross-tenant read/write. This is the #1 security footgun.
   - **`internal*` for anything not client-callable**; keep the public surface minimal (you already used this pattern for the Woo webhook — `convex/wooCommerceInternal.ts`).
   - **Rate Limiter** (`@convex-dev/rate-limiter`) — replaces the implicit throttling the server-action tier gave.
2. **Reads → native**, per domain: flip the built-but-OFF `NEXT_PUBLIC_NATIVE_*` flags; convert the remaining "signal-only" reads (project services, crew scheduling, maintenance, supplier orders, saved views) to real native bundles; notifications poller → subscription. Keep read-set breadth minimal (Appendix B: split org-wide/high-churn slices — availability, counters, presence — into their own narrow queries).
3. **Writes → browser-direct**, per domain, **two-hop**: bake `NATIVE_*_WRITES` (server routes through the native mutation — no-rebuild rollback) first, parity-test, then `NEXT_PUBLIC_NATIVE_*_OPTIMISTIC` (browser-direct). Parity-gated at each hop.
4. **Optimistic by consequence (NOT blanket):** notes/status/reorder/tags → optimistic (`withOptimisticUpdate`); **warehouse checkout/checkin, archive/delete, pricing, scheduling → explicit pending→confirmed/failed, never a fake success** (rollback can't undo an operator handing out gear or a quote sent).
5. **Bulk = native array mutations, single-call invariant (ENFORCED GATE):** every surface where a user acts on >1 item resolves to exactly ONE Convex array mutation — no client fan-out, no server-side per-item Convex loop. A domain does not ship native until each multi-select action is a single array mutation. Preserve **partial-success** (`{succeeded, errors}`) for warehouse/inventory bulk (one bad item can't abort a 200-item deploy); atomic all-or-nothing only for genuinely transactional sets. **Benchmark sizing** (50/200/500/1000 × 1/4/8 concurrent) against Convex's 16k-write / 1s-CPU limits before trusting a per-call ceiling; chunk overflow via scheduler/Workpool. Per-item deterministic `auditId` for OCC-retry safety. The complete audited multi-select inventory + specific gaps is in the plan's Appendix.
6. **Efficiency (Appendix B remainder):** the `projectEquipment.browserBundle` org-wide narrowing + per-row `getLock`/`getReviewMarker` collapse (task #4 in the tracker). Fold in as you touch each domain.
7. **End state:** the server-action **data layer is deleted** — **but EXEMPT `src/lib/*-read.ts`** (the `getConvexClient` service-token read helpers; PDF/CSV run in Node and can't use browser `useQuery`, so this seam must survive). Also keep the auth/admin/settings server actions that are legitimately server-only.
