Nothing here is "tour state".

  • All four ticks are derived from real rows. Go and add five models by hand, ignoring every prompt, and the list is simply ticked when you come back.

Start with the model, not the unit.

A model is the thing you rent — "MAC Aura XB". An asset is one physical unit of it, with its own tag and history.

Twelve fixtures on a shelf is one model and twelve assets. You'll add the first of those next.

Serialised if it has a serial. Bulk if you count it in a crate.

No spotlight. No overlay. No dimmed page.

  • The coaching renders into the helper rail the form already has, so it sits in the layout instead of floating above it.
  • That is a deliberate call, not a shortcut. A spotlight library would have to coexist with the app's modal locks — the exact area with the worst bug history in this codebase.
  • It also means the tips scroll, resize and print like everything else, and can never trap a click.
  • "Hide tips" is honest — it hides them, it does not abandon the checklist.

If they never come back

The 30-day ladder

  1. Day 1 · 3 · 7 Nudge"You're two steps from your first quote." Encouraging
  2. Day 23 Heads-up"We'll archive Northlight in 7 days. Add anything at all and we won't." Plain
  3. Day 29 Last call24 hours' notice. Plain
  4. Day 30 ArchivedReversible, with a one-click link to bring it back. Not a goodbye

Only companies that did genuinely nothing since the day they signed up can enter this ladder — no gear, no jobs, no activity, one member. A real company that set up properly in March and goes quiet over winter can never match, however long it idles. Adding a single model exits the ladder permanently.

Reversible is what licenses the automation.

  • Nothing irreversible is ever automated. The end of this ladder is an archive, warned twice and undone in one click.
  • Five emails, ever. An onboarding sequence that keeps nagging is worse than an abandoned account.
  • The day-30 email is deliberately not a farewell — saying otherwise would be untrue.

What this is

A static mockup of the flow described in docs/designs/onboarding-and-activation.md. Nothing here is wired up — no fields submit and no buttons navigate. Colours, type, radii, shadows and spacing are taken from the live RVLT tokens rather than approximated, so the screens should read as the same product.

Company name, ABN, addresses and job numbers are invented for the mock.
