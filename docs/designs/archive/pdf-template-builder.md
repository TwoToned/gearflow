# PDF Template Builder — Design Document

## Problem Statement

GearFlow's current PDF generation system has two critical issues:
1. **Multi-page documents break.** The gearflowTable plugin draws content from a fixed Y-position with no page-break awareness. Projects with 20+ line items produce PDFs where content runs off the page.
2. **Limited customization.** Users can only toggle fields on/off. They can't reorder sections, add custom content, or control layout.

## Vision

Stripe's invoice builder meets Notion's block editor. A section-based drag-and-drop template builder where users design professional multi-page documents by reordering typed sections, adding custom content with dynamic tokens, and previewing with real project data.

## Architecture

### Section-Based Model

Templates are stored as an ordered array of typed sections. Each section has:
- **Type**: header, client-details, project-details, table, totals, notes, signature, custom-text, crew-table, spacer, page-break
- **Settings**: Type-specific configuration (column visibility, text content, signature count, etc.)
- **Visibility rules**: Document type filter + data conditions (e.g., "only show on delivery dockets")
- **Content**: For custom-text sections — text with `{token}` placeholders

### Generation Pipeline

```
Template (sections[]) → Resolve Brand Template → Evaluate Conditions → Resolve Tokens → Paginate → pdfme generate()
```

The engine computes Y-positions dynamically per page, repeats header/footer sections on each page, and splits the table across pages (never mid-row).

### Data Model

**New: BrandTemplate** — Org-level brand settings (header, footer, accent color) that document templates inherit from.

**Extended: DocumentTemplate** — New `sections` (JSON), `brandTemplateId` (FK), `thumbnailData` (base64) columns. Legacy `basePdf`/`schemas` columns preserved for backward compatibility.

**New type: TemplateSection** — `{ id, type, settings, visibility, content, order }`

### UI

3-panel editor:
- **Left**: Draggable section list (dnd-kit) with add/remove/reorder
- **Center**: Per-section settings panel (toggles, text inputs, token autocomplete)
- **Right**: Live PDF preview (pdf.js canvas) with project picker dropdown

## Accepted Scope

### Core
- Multi-page auto-pagination for all 6 project document types
- Section-based drag-and-drop template builder
- Configurable sections: header, client details, project details, table, totals, notes, signature, custom text
- Live PDF preview with debounced regeneration
- Replace existing pdfme Designer with new section builder

### Expansions (all accepted)
1. **Token system** — `{client_name}`, `{project.venue}` etc. in any text field. Autocomplete dropdown. Whitelist-validated.
2. **Conditional visibility** — Per-section rules: document type filter + data conditions (field exists/equals).
3. **Template inheritance** — Brand template → document templates inherit header/footer/colors. Change once, updates all.
4. **Real project preview** — Project picker dropdown in editor. Preview with actual project data instead of sample data.
5. **Template thumbnails** — Auto-generated on save/publish. Shown in template list and template picker.
6. **Export/import** — Portable JSON format. Strip org-specific data on export. Zod-validated on import.
7. **Page break indicators** — Dotted lines in editor showing estimated page break positions.
8. **Undo/redo** — History stack for section operations. Ctrl+Z / Ctrl+Shift+Z.

## Migration Strategy

1. **Additive schema migration** — New columns + new table. Zero risk.
2. **Data migration** — Convert existing `DocumentTemplate.settings` → `sections[]`. Legacy templates continue working on old pipeline.
3. **Coexistence** — Generation pipeline checks: `sections[]` populated → new pipeline, else → legacy pipeline.
4. **Future cleanup** — Remove legacy pipeline after all orgs migrated (tracked in TODOS.md).

## Security

- Token resolver uses **whitelist** of allowed field names (no arbitrary property access)
- Template export **strips** org-specific data (logo, orgId)
- Section count limit (50) and text length limit (5000 chars)
- Import validated with Zod schema, size-limited

## Not In Scope

- Full canvas WYSIWYG editor (dynamic data conflicts with pixel-perfect placement)
- T&T report template builder (Phase 2 — tracked in TODOS.md)
- Email template builder (Phase 3)
- Real-time collaborative editing
- Template marketplace
- Custom fonts beyond Helvetica (pdfme/pdf-lib limitation)
